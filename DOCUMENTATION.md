## 1. Термины, определения и глоссарий проекта

В соответствии с разделом «Термины и определения» официального Технического задания 2026:

* **Обязательные расходы («Миска жизни»)** — товары или действия, жизненно необходимые питомцу регулярно (корм, вода, гигиена, витамины), от которых напрямую зависят показатели сытости ($S$) и здоровья ($H$). В плане бюджета относятся к направлению обязательных трат.
* **Необязательные расходы («Сундучок радости»)** — товары или действия, влияющие на настроение питомца ($M$), но не критичные для выживания (игрушки, лакомства, аксессуары). Отказ от них или перенос на будущие периоды допустимы и не являются ошибкой.
* **Накопления («Копилка мечты»)** — часть игровой валюты, отложенная пользователем в целевую копилку и хранящаяся отдельно от свободного баланса.
* **План личного бюджета (план)** — предварительное распределение доступной на игровой период суммы по трём направлениям: обязательные расходы, необязательные траты, накопления. Составляется до начала совершения трат и служит базой для сопоставления с фактом.
* **Фактическое исполнение бюджета (факт)** — итог использования игровой валюты за период, отражающий суммы, реально потраченные по каждому направлению, а также объём пополнения копилки.
* **Финансовая цель (цель)** — предмет с понятной стоимостью и сроком (мяч — 400 монет, наушники — 700 монет, самокат — 1000 монет), ради которого ребёнок осуществляет сбережения.
* **Игровая валюта** — условные единицы («монеты» / «крокетсы»), начисляемые за квесты, карманные деньги и помощь по дому. Не имеют реальной стоимости, не продаются за реальные рубли и не подлежат обмену на материальные призы.
* **Игровой период** — завершённый цикл финансовых решений (в прототипе — один игровой день календаря), по итогам которого пересчитываются бюджет, накопления, статы и развитие питомца.
* **Состояние питомца** — обратимые текущие характеристики персонажа: сытость ($S$), здоровье ($H$), настроение ($M$), визуализируемые на главном экране в виде анимированного пиксельного питомца и шкал-орбов.
* **Стадия развития (рост питомца)** — долгосрочная характеристика эволюции персонажа («Малыш» $\to$ «Подросток» $\to$ «Взрослый»), изменяющаяся по сумме очков заботы (*Care Points*) за серию периодов.
* **Локальный игровой профиль** — изолированный набор данных игрока, хранящийся исключительно в локальной базе данных на устройстве.
* **Тестовый профиль** — профиль для экспертной проверки, позволяющий в любой момент пройти сценарий заново через сброс в один клик.
* **Демонстрационный режим (Demo Mode)** — режим работы приложения для жюри, в котором шаги сценария и смена игровых дней проходятся подряд, без ожидания календарных дат и без блокировок контента.
* **Обязательный сценарий** — эталонная последовательность из 12 шагов Приложения А ТЗ.

## 2. Назначение продукта, состав репозитория и быстрый запуск

### 2.1. Назначение продукта
«ФинПитомец» (FinPet) — обучающее мобильное Android-приложение, формирующее у детей 7–11 лет ключевые базовые навыки финансовой культуры:
1. **Ограниченность ресурсов:** понимание того, что нельзя купить всё сразу за один раз.
2. **Приоритет необходимого перед желаемым:** сначала обеспечивается сытость и здоровье питомца, затем — развлечения.
3. **Планирование личного бюджета:** разделение доступных средств на три корзины («Обязательное», «Желаемое», «Копилка») с контролем лимита и остатка.
4. **Регулярные накопления:** постановка краткосрочной финансовой цели и систематическое отчисление средств.
5. **Безопасная ошибка:** принятие решений в безопасной среде без реальных финансовых рисков, рекламы и пейволлов. Питомец не может погибнуть; ошибка превращается в понятную задачу восстановления.
6. **Анализ последствий:** наглядная обратная связь «План vs Факт» после каждого игрового дня.

### 2.3. Быстрый запуск для эксперта

Приложение полностью автономно и не требует запуска вспомогательных бэкенд-серверов или баз данных.

1. **Клонирование репозитория:**
   ```bash
   git clone https://github.com/4l1vk4/LCT-hack.git
   cd LCT-hack
   ```

2. **Сборка Debug APK из терминала:**
   ```bash
   ./gradlew assembleDebug
   ```

3. **Установка на подключенное устройство или эмулятор:**
   ```bash
   adb install -r app/build/outputs/apk/debug/app-debug.apk
   ```

4. **Запуск автоматических тестов:**
   ```bash
   ./gradlew testDebugUnitTest
   ```

### 3.3. Сборка и подпись релизной версии (Signed Release APK)
В соответствии с разделом 3.3 ТЗ: *«Для финальной проверки предоставляется подписанный APK-файл релизной сборки, устанавливаемый без среды разработки»*.

В конфигурации `release` активирован R8 с полной минификацией байткода и удалением неиспользуемых ресурсов (`isMinifyEnabled = true`, `isShrinkResources = true`).

1. **Сборка релизного APK:**
   ```bash
   ./gradlew assembleRelease
   ```
   Собранный файл: `app/build/outputs/apk/release/app-release-unsigned.apk`

2. **Создание релизного ключа подписи (при отсутствии):**
   ```bash
   keytool -genkey -v -keystore release.keystore -alias finpet -keyalg RSA -keysize 2048 -validity 10000 -storepass password123 -keypass password123 -dname "CN=FinPet, OU=Dev, O=FinPet, L=Moscow, C=RU"
   ```

3. **Выравнивание и подпись APK через Android SDK Build-Tools:**
   ```bash
   zipalign -v -p 4 app/build/outputs/apk/release/app-release-unsigned.apk app-release-aligned.apk
   apksigner sign --ks release.keystore --ks-pass pass:password123 --key-pass pass:password123 --out app-release-signed.apk app-release-aligned.apk
   ```

4. **Проверка подписи:**
   ```bash
   apksigner verify app-release-signed.apk
   ```
   Полученный файл `app-release-signed.apk` готов к установке на любое физическое устройство без Android Studio командой:
   ```bash
   adb install -r app-release-signed.apk
   ```

## 4. Функциональная и компонентная архитектура решения

### 4.1. Архитектурный паттерн и слои Clean Architecture

Проект спроектирован по принципам Clean Architecture и рекомендациям Google Modern Android Architecture с однонаправленным потоком данных (Unidirectional Data Flow / MVI):

```text
┌────────────────────────────────────────────────────────────────────────┐
│                          UI LAYER (Presentation)                       │
│  Jetpack Compose Screens: FinikScreen, MapScreen, CalendarScreen,      │
│  AdultScreen, SettingsScreen, Onboarding. Управление: MainViewModel    │
└────────────────────────────────────▲───────────────────────────────────┘
                                     │ StateFlow / Events
┌────────────────────────────────────▼───────────────────────────────────┐
│                          DOMAIN LAYER (Use Cases)                      │
│  Бизнес-логика без Android SDK: PetEconomyCalculator, ConfirmBudget,   │
│  MakePurchase, DepositToGoal, WithdrawFromGoal, QuestEngine            │
└────────────────────────────────────▲───────────────────────────────────┘
                                     │ Repository Interfaces
┌────────────────────────────────────▼───────────────────────────────────┐
│                           DATA LAYER (Storage)                         │
│  Room SQLite Database (7 таблиц), DataStore Preferences,               │
│  ContentRepository (assets/content/*.json), NotificationManager        │
└────────────────────────────────────────────────────────────────────────┘
```

1. **Data Layer:**
   * Абстрагирован интерфейсом `FinPetRepository`.
   * Обеспечивает транзакционность через метод `inTransaction { ... }`, исключая рассинхронизацию баланса, покупок и целей при сбоях.
   * Парсит декларативные учебные ресурсы `assets/content/` с помощью `kotlinx.serialization`.
2. **Domain Layer:**
   * Содержит изолированные чистые модели (`BudgetPlan`, `ActualExpenses`, `BudgetCompliance`, `GrowthStage`, `PetStats`).
   * Реализует математические функции экономики в синглтоне `PetEconomyCalculator`.
   * Не зависит от Android Framework, что обеспечивает мгновенное выполнение Unit-тестов на JVM (< 2 секунд).
3. **UI / Presentation Layer:**
   * Декларативный UI на Jetpack Compose с Material 3.
   * `MainViewModel` выступает единым источником правды (*Single Source of Truth*), отдавая иммутабельный `StateFlow<MainUiState>`.
   * Пользовательские действия преобразуются в строго типизированные интенты / вызовы Use Cases.

### 4.2. Автономность и отсутствие серверной части (Offline-First)

В полном соответствии с разделом 3.2 ТЗ: *«Серверная часть. Для обязательного прототипа не требуется»*:
* Серверная часть отсутствует намеренно: приложение работает на 100% локально.
* В коде отсутствует сетевой клиент (Retrofit, Ktor), а в манифесте отсутствует разрешение `android.permission.INTERNET`.
* База данных SQLite автоматически инициализируется демонстрационными данными при первом старте и мгновенно восстанавливается после сброса.

## 5. Структура данных и схема базы данных Room SQLite

База данных управляется через Room 2.6.1 (`finpet_database.db`, версия схемы: 4).

### 5.1. Таблица `profiles` (Локальный профиль игрока)
Хранит игровое состояние персонажа и финансовый статус:

| Поле | Тип данных | Описание и значение по умолчанию |
|---|---|---|
| `id` | `TEXT PRIMARY KEY` | Идентификатор профиля (`"default_player"`) |
| `petName` | `TEXT` | Имя питомца («Финни») |
| `petType` | `TEXT` | Вид животного (`"CAT"`) |
| `bodyColor` | `INTEGER` | Цветовой оттенок персонажа (`0xFFFFA726`) |
| `eyesType` | `INTEGER` | Тип глаз (1..3) |
| `accessoryId` | `TEXT` | Надетое украшение (`"none"`, `"glasses"`, `"tie"`, `"clown_nose"`) |
| `balance` | `INTEGER` | Свободный баланс монет (стартовый: 200) |
| `currentPeriodIndex` | `INTEGER` | Номер текущего дня календаря (1..28) |
| `carePoints` | `INTEGER` | Накопленные очки заботы (0..∞) |
| `growthStage` | `TEXT` | Стадия роста (`"BABY"`, `"TEEN"`, `"ADULT"`) |
| `satiety` | `INTEGER` | Сытость (0..100) |
| `health` | `INTEGER` | Здоровье (0..100) |
| `mood` | `INTEGER` | Настроение (0..100) |
| `activeGoalId` | `TEXT?` | ID активной цели в копилке |

## 7. Математическая модель и формулы игровой экономики

Все алгоритмы расчёта сосредоточены в синглтоне `PetEconomyCalculator.kt` и покрыты 18 изолированными Unit-тестами.

### 7.1. Денежные потоки и баланс
* **Стартовый капитал:** 200 монет при создании профиля.
* **Карманные деньги:** начисляются регулярно раз в неделю по понедельникам (дни 1, 8, 15, 22) в размере 200 монет:
  $$\text{Income}(day) = \begin{cases} 200, & \text{если } (day - 1) \pmod 7 = 0 \\ 0, & \text{иначе} \end{cases}$$
* **Задания школы:** +20..50 монет за правильное решение финансовых ситуаций.
* **Помощь по дому (мини-игры):** +15..25 монет за уборку, мытьё посуды и полов.
* **Родительские поощрения:** произвольное начисление монет взрослым в защищённом разделе.

### 7.2. Личный бюджет (Правило трёх корзин)
При планировании дня ребёнок распределяет средства:
$$\text{Plan}_{\text{total}} = \text{Plan}_{\text{mandatory}} + \text{Plan}_{\text{optional}} + \text{Plan}_{\text{savings}}$$
Условие валидации бюджета:
$$\text{Plan}_{\text{total}} \le \text{AvailableBalance}$$
$$\text{Remainder} = \text{AvailableBalance} - \text{Plan}_{\text{total}}$$
Если $\text{Plan}_{\text{total}} > \text{AvailableBalance}$, план считается некорректным, и утверждение блокируется.

### 7.3. Жизненные показатели питомца (шкалы 0..100)

#### Сытость ($S$)
* $S = 100$ — если куплен «Сытный обед» ($\ge 30$ монет) или выставлена миска;
* $S = \min(60, S_{\text{prev}} + 15)$ — если куплена только вода ($\ge 10$ монет);
* $S = 30$ — при первом пропуске кормления ($S_{\text{prev}} > 30$);
* $S = \max(0, S_{\text{prev}} - 15)$ — при повторном отсутствии еды (хроническое голодание).

#### Здоровье ($H$)
* $H = 100$ — если обязательные расходы закрыты и сытость $S \ge 60$;
* $H = 90$ — если куплены витамины / лекарства;
* $H = 60$ — при первом пропуске ухода;
* $H = \max(0, H_{\text{prev}} - 20)$ — при падении сытости ниже 30.

#### Настроение ($M$)
Базовое значение $M_{\text{base}} = \min(M_{\text{prev}}, 60)$ при $S < 50$, иначе $M_{\text{prev}}$.
$$M = M_{\text{base}} + \Delta_{\text{opt}} + \Delta_{\text{sav}} - \text{Penalty}_{\text{overspend}} - \text{Penalty}_{\text{hunger}}$$
где:
* $\Delta_{\text{opt}} = \min(35, (\text{Actual}_{\text{optional}} / 10) \cdot 10)$ — бонус за игрушки и лакомства;
* $\Delta_{\text{sav}} = 10$ — похвала за выполнение плана копилки;
* $\text{Penalty}_{\text{overspend}} = 20$ — штраф за превышение лимита необязательных трат;
* $\text{Penalty}_{\text{hunger}} = 30 + (30 - S)$ — прогрессивный штраф за голодание.

#### Эффективное настроение для UI и анимаций
$$\text{EffectiveMood} = \text{round}(0.60 \cdot M + 0.20 \cdot S + 0.20 \cdot H) - \text{Penalty}_{\text{degrade}}$$
где $\text{Penalty}_{\text{degrade}} = (50 - S) \cdot 0.5 + (60 - H) \cdot 0.6$ при падении шкал.
* $\text{EffectiveMood} \ge 70$ $\to$ **Счастлив** (`HAPPY`);
* $40 \le \text{EffectiveMood} < 70$ $\to$ **Спокоен** (`NEUTRAL`);
* $\text{EffectiveMood} < 40$ $\to$ **Грустит** (`SAD`).

### 7.4. Расчёт соответствия бюджета («План vs Факт»)

Для каждой корзины рассчитывается точность исполнения:
1. **Обязательное ($\text{Score}_{\text{mand}}$):**
   * Приоритет жизни: если питомец голодает, $\text{Score}_{\text{mand}} \le 0.15$;
   * Если план закрыт и питомец сыт: $1.0$;
   * При перерасходе: $\max(0.0, 1.0 - \frac{\text{Actual}_{\text{mand}} - \text{Plan}_{\text{mand}}}{\max(\text{Plan}_{\text{mand}}, 30)})$.
2. **Желаемое ($\text{Score}_{\text{opt}}$):**
   * Экономия поощряется: если $\text{Actual}_{\text{opt}} \le \text{Plan}_{\text{opt}}$, оценка равна $1.0$ (штрафа за неизрасходованные на развлечения деньги нет!);
   * При перерасходе: пропорциональное снижение оценки.
3. **Копилка ($\text{Score}_{\text{sav}}$):**
   * Превышение взноса поощряется ($1.0$);
   * Если питомец голодает, накопления не признаются успехом ($\text{Score}_{\text{sav}} \le 0.15$).

Итоговый процент дисциплины:
$$\text{BasePercent} = \text{round}\left(\frac{\text{Score}_{\text{mand}} + \text{Score}_{\text{opt}} + \text{Score}_{\text{sav}}}{3} \cdot 100\right)$$
$$\text{TotalPercent} = \text{BasePercent} - \text{Penalty}_{\text{overspend}} - \text{Penalty}_{\text{hunger}} - \text{Penalty}_{\text{withdrawn}} - \text{Penalty}_{\text{borrowed}}$$
Бюджет признаётся дисциплинированным (`isDisciplined = true`), если $\text{TotalPercent} \ge 75\%$ и питомец не голоден.

### 7.5. Очки заботы (*Care Points*) и эволюция питомца
За каждый закрытый день начисляется от 0 до 4 очков заботы:
* **+2 очка:** базовые потребности удовлетворены ($S \ge 60$ и $H \ge 80$);
* **+1 очко:** соблюдён плановый взнос в копилку (или внесено $\ge 20$ монет);
* **+1 очко:** достигнута высокая финансовая дисциплина ($\text{TotalPercent} \ge 75\%$).

**Пороги стадий роста (`GrowthStage.kt`):**
* **«Малыш» (BABY):** $0..27$ очков (базовый котёнок);
* **«Подросток» (TEEN):** $28..69$ очков (подросший персонаж, открывается расширенный гардероб);
* **«Взрослый» (ADULT):** $\ge 70$ очков (взрослый мудрый кот с отличительным знаком заботы).  
*(Примечание: при идеальном уходе +4 очка в день переход в «Подросток» занимает ровно 7 дней — одну игровую неделю, а во «Взрослый» — около 18 дней).*

### 7.6. Алгоритм безопасной ошибки и возвращения питомца
* Питомец не может погибнуть.
* Если игрок несколько дней подряд игнорирует кормление, эффективное настроение падает до 0%, и кот временно прячется («убегает во двор»).
* Рост питомца замораживается.
* Для возвращения ребёнку не нужно вносить реальные деньги: достаточно купить в магазине миску корма за 60 монет и выставить её у домика. На следующий день питомец возвращается домой со статусами $S=80, H=70, M=60$.

## 8. Карта образовательного контента и привязка к компетенциям Минфина РФ

Образовательный контент разработан на базе **Единой рамки компетенций в области финансовой грамотности для учащихся начального общего образования** (утверждена протоколом МКК от 5 марта 2026 года) и охватывает 3 ключевые предметные области:
1. **Личный бюджет (BUDGETING)**
2. **Сбережения и цели (SAVINGS)**
3. **Покупки и траты (PURCHASES)**

### 8.1. Разнообразие игровых механик заданий
В соответствии с п. 2.5.8 ТЗ (*«Задания... не ограничиваются выбором ответа из предложенных вариантов»*), в банке из 18 квестов реализовано 4 интерактивных формата:
1. `CHOICE`: сюжетные дилеммы с выбором из 2–3 вариантов и моментальным разбором последствий.
2. `TEXT_INPUT`: финансовые загадки с текстовым вводом ключевых терминов (проверка с нечувствительностью к регистру, пробелам и морфологическим синонимам).

## 9. Обоснование UX/UI-решений и настройки доступности

Интерфейс спроектирован в строгом соответствии с рекомендациями Google Material 3 и руководствами по доступности (Android Accessibility Guidelines) с учётом детской эргономики:

1. **Крупные сенсорные области (Touch Targets):** все интерактивные кнопки, иконки навигации и переключатели имеют физический размер не менее $48 \times 48$ dp, исключая случайные промахи детских пальцев.
2. **Разборчивая типографика:**
   * Базовый размер шрифта для чтения текстов и диалогов составляет не менее 16 sp.
   * Заголовки и числовые балансы выполнены крупным кеглем от 20 sp до 28 sp.
   * Приложение поддерживает системное масштабирование шрифта Android без искажения вёрстки.
3. **Цветовой комфорт и контрастность:**
   * Мягкая пиксель-арт палитра с тёплым фоном (`#FFF8F0` / `#FFF9E6`) и контрастным тёмно-коричневым текстом (`#2C2016`) снижает утомляемость глаз.
   * **Мультимодальность:** цвет никогда не является единственным способом передачи статуса. Любое состояние (сытость, здоровье, ошибка, дефицит средств) дублируется понятной пиктограммой и текстовым описанием.
4. **Психологическая безопасность:**
   * Полное отсутствие стресс-факторов: таймеров реального времени, механик гибели персонажа и штрафов за скорость.
   * Тексты не стыдят ребёнка за ошибки, а объясняют причинно-следственную связь и предлагают добрый шаг к исправлению ситуации.
5. **Настройки аудиокомфорта:**
   * В разделе настроек предусмотрены раздельные независимые регуляторы громкости фоновой музыки (`soundtrack.mp3`) и звуковых эффектов с моментальным сохранением в DataStore Preferences.
   * Все ключевые события дублируются визуальными анимациями.

## 10. Политика разрешений Android, безопасность данных и процедура удаления профиля

### 10.1. Полное обоснование разрешений Android (`AndroidManifest.xml`)

Приложение запрашивает исключительно два разрешения, необходимые для локального взаимодействия с ребёнком:

| Разрешение Android | Класс опасности | Техническое обоснование необходимости |
|---|:---:|---|
| `android.permission.POST_NOTIFICATIONS` | Runtime (Normal) | Необходимо на Android 13+ для показа **локальных** дружелюбных уведомлений-напоминаний («Пора покормить Финни», «Наступил понедельник — выданы карманные деньги»). Отключается в системных настройках в 1 клик. Не связано с сетью. |
| `android.permission.RECEIVE_BOOT_COMPLETED` | Normal | Необходимо для восстановления локальных таймеров `AlarmManager` после плановой перезагрузки смартфона, чтобы напоминания о питомце продолжали работать без запуска приложения. |

**Абсолютно отсутствуют в манифесте:**
* `android.permission.INTERNET` (100% оффлайн-приложение, сетевые утечки невозможны технически).
* Доступ к камере (`CAMERA`), микрофону (`RECORD_AUDIO`), геопозиции (`ACCESS_FINE_LOCATION`), контактам (`READ_CONTACTS`) и внешнему хранилищу (`READ_EXTERNAL_STORAGE`).

### 10.2. Состав сохраняемых данных и соответствие 152-ФЗ
Приложение собирает и хранит исключительно внутриигровой прогресс:
* Вымышленное имя персонажа (например, «Финни»).
* Числовые балансы монет, шкал сытости, здоровья и очков заботы.
* Локальную историю покупок в виртуальном магазине.

Никакие персональные данные (ФИО ребёнка или родителей, номера телефонов, e-mail, геопозиция, рекламные ID Google AID) не запрашиваются, не собираются и не передаются. Приложение полностью соответствует требованиям Федерального закона № 152-ФЗ «О персональных данных» и рекомендациям по защите детей в цифровой среде.

### 10.3. Процедура сброса и удаления профиля
В защищённом родительском разделе (`AdultScreen.kt`) реализован механизм полного сброса данных в 1 клик (`ResetDemoProfileUseCase`). При его активации:
1. База данных SQLite полностью очищается.
2. Профиль возвращается в состояние 1 дня с исходным балансом в 200 монет.
3. Эксперт или родитель могут начать прохождение сценария с чистого листа без переустановки APK.
