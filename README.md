# ФинПитомец (FinPet)

Обучающая мобильная игра по финансовой грамотности для детей 7–11 лет.  
Проект разработан для хакатона «Лидеры цифровой трансформации» (Задача №6: Департамент финансов города Москвы).  
Пакет приложения: `ru.finpet.kids`

---

## О проекте

Приложение помогает детям младшего школьного возраста познакомиться с базовыми правилами обращения с личными финансами. Игровой процесс построен вокруг заботы о виртуальном питомце: ребёнок регулярно получает карманные деньги и учится распределять их самостоятельно.

Логика игры построена на приоритетах:
1. Обязательные расходы: регулярная покупка еды, воды и забота о здоровье питомца.
2. Необязательные траты: игрушки, лакомства и аксессуары.
3. Накопления: регулярные отчисления в копилку на выбранную цель (спортивный мяч, наушники, самокат).

В основу обучающего контента заложена Единая рамка компетенций в области финансовой грамотности и финансовой культуры (Минфин РФ и Банк России), а также материалы проекта «Открытый бюджет города Москвы».

### Принципы реализации
* Наглядная причинно-следственная связь: если не закрыть базовые потребности питомца и потратить всё на развлечения, питомец проголодается и загрустит, но не погибнет. Ошибку всегда можно исправить в следующем периоде.
* Полная автономность и безопасность: в коде нет опасных Android-разрешений, рекламы, встроенных покупок и сетевых запросов. Все данные хранятся локально на устройстве.
* Защищённый родительский раздел: экран для взрослых закрыт математической капчей. В нём родитель может посмотреть динамику освоения навыков ребёнком, начислить поощрительные монеты за реальные дела или сбросить тестовый профиль.

## Быстрый старт для жюри

### Сборка и видеодемонстрация
* Готовый APK: `app/build/outputs/apk/debug/app-debug.apk` (доступен в артефактах сборки и релизах).
* Резервная видеозапись демонстрации сценария (до 3 минут): [Ссылка на видео](#).

### Требования к окружению
* JDK: Java 17
* Android SDK: compileSdk 34, minSdk 26 (поддержка Android 8.0 и выше)
* Gradle: 8.9 (через проектный скрипт `gradlew`)

### Сборка из терминала

```bash
# Клонирование репозитория
git clone https://github.com/4l1vk4/LCT-hack.git
cd LCT-hack

# Сборка Debug APK
./gradlew assembleDebug

# Установка на подключенное устройство или эмулятор
./gradlew installDebug
# либо через adb напрямую:
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

Запуск тестов бизнес-логики:
```bash
./gradlew testDebugUnitTest
```

## Сквозной сценарий тестирования (Приложение А)

Маршрут проверки 12 шагов регламента (время прохождения: около 3 минут):

| Шаг | Действие в приложении | Что проверяется |
|:---:|---|---|
| 1 | Запуск приложения | Показ онбординга с объяснением логики трёх корзин: Обязательное, Желаемое, Копилка. |
| 2–3 | Выбор внешности и имени питомца | Создание локального профиля без сбора персональных данных. |
| 4 | Переход на главный экран | Начисление стартового капитала (200 монет), отображение базовых показателей питомца. |
| 5 | Вкладка «Календарь» -> «План бюджета» | Распределение суммы по 3 корзинам, проверка валидации лимита и расчёт свободного остатка. |
| 6 | Вкладка «Город» -> локация «Школа» | Прохождение интерактивного квеста с выбором варианта, показ обратной связи с объяснением. |
| 7 | Вкладка «Город» -> локация «Магазин» | Покупка еды (обязательное) и мячика (желаемое). Проверка блокировки покупки при нехватке монет. |
| 8 | Вкладка «Город» -> локация «Банк» | Выбор цели накоплений и пополнение копилки. Расчёт ориентировочного срока достижения. |
| 9 | Переход к следующему дню | Показ экрана итогов «План vs Факт», расчёт процента соблюдения бюджета и начисление очков заботы. |
| 10 | Развитие персонажа | При накоплении очков заботы питомец переходит на следующую стадию роста (Малыш -> Подросток -> Взрослый). |
| 11 | Принудительное закрытие (swipe-to-kill) и повторный запуск | Проверка персистентности базы данных Room: баланс, состояние и история сохраняются полностью. |
| 12 | Вкладка «Родителям» | Математический барьер (решение примера), просмотр отчёта по компетенциям, начисление бонуса и кнопка сброса профиля. |

## Архитектура и стек технологий

Проект реализован в рамках одного модуля `:app` с чётким разделением слоёв по Clean Architecture и реактивным подходом MVI/MVVM. Образовательный контент вынесен в JSON-ресурсы, что позволяет обновлять задания и каталог без изменения кода приложения.

```text
ru.finpet.kids/
├── core/
│   ├── data/             // Room SQLite (Entities, DAO), DataStore Preferences, репозитории
│   ├── domain/           // Бизнес-модели, Use Cases, калькулятор игровой экономики
│   └── designsystem/     // Темизация Material 3, пиксельная палитра, тач-таргеты от 48dp
├── feature/
│   ├── onboarding/       // Выбор внешности и ввод имени персонажа
│   ├── finik/            // Экран питомца (анимации, шкалы состояния, гардероб)
│   ├── map/              // Интерактивная карта города (Дом, Школа, Магазин, Банк)
│   ├── calendar/         // Календарь на 28 дней, планирование бюджета, регулярные траты
│   ├── adult/            // Раздел для взрослого (математический гейт, аналитика, сброс)
│   └── settings/         // Управление звуком, музыкой и хранилищем
└── assets/content/       // purchases.json, quests.json, goals.json
```

### Стек компонентов
* Интерфейс: Jetpack Compose, Material 3, Navigation Compose.
* Управление состоянием и DI: AndroidX ViewModel, Google Hilt.
* Хранилище: Room 2.6.1 SQLite, Jetpack DataStore Preferences.
* Асинхронность: Kotlin Coroutines, StateFlow, SharedFlow.
* Сериализация данных: kotlinx.serialization.
* Графика: Coil Compose (загрузка и кэширование спрайтов и GIF-анимаций).
* Тестирование: JUnit, MockK, CashApp Turbine, Coroutines Test.

## Игровая экономика и математическая модель

Логика расчётов изолирована в объекте `PetEconomyCalculator` и покрыта модульными тестами.

### 1. Денежные потоки
* Начальный баланс: 200 монет при создании нового питомца.
* Карманные деньги: 200 монет начисляются по понедельникам (1, 8, 15 и 22 дни календаря).
* Награды за квесты: от 20 до 40 монет в зависимости от выбранного решения.
* Родительские поощрения: начисление монет взрослым с фиксацией причины в истории.

### 2. Распределение бюджета (3 корзины)
$$\text{План} = \text{Обязательное} + \text{Желаемое} + \text{Копилка} \le \text{Баланс}$$
$$\text{Свободный остаток} = \text{Баланс} - \text{План}$$

### 3. Шкалы состояния питомца (диапазон 0..100)
* Сытость ($S$): 100 при покупке еды; 60 при покупке только воды; падает до 30 при разовом пропуске обязательных трат и до 0 при длительном отсутствии питания.
* Здоровье ($H$): 100 при своевременном закрытии обязательных нужд; восстанавливается витаминами до 90; снижается при голодании.
* Настроение ($M$): повышается от покупки игрушек (+25), лакомств (+15) и взносов в копилку (+10); снижается при голоде (-30) и при превышении лимита необязательных трат (-20).
* Эффективное настроение:
  $$\text{EffectiveMood} = 0.6 \cdot M + 0.2 \cdot S + 0.2 \cdot H - \text{штрафы за голод}$$
  * от 70 до 100: Счастлив (HAPPY);
  * от 40 до 69: Спокоен (NEUTRAL);
  * меньше 40: Грустит (SAD).

### 4. Очки заботы и стадии роста
За каждый завершённый игровой день начисляется от 0 до 4 очков заботы (Care Points):
* +2 очка: обязательные потребности закрыты (сыт и здоров);
* +1 очко: выполнен плановый взнос в копилку;
* +1 очко: бюджет соблюдён дисциплинированно (соответствие плана и факта от 75%).

Стадии развития персонажа:
* Малыш: 0–4 очка (базовый спрайт, начальный уровень);
* Подросток: 5–9 очков (подросший персонаж, доступ к гардеробу с аксессуарами);
* Взрослый: 10 и более очков (финальная форма питомца с отличительным знаком).

## Безопасность, приватность и публикация в RuStore

* Ноль опасных разрешений: файл `AndroidManifest.xml` не запрашивает доступ к камере, микрофону, контактам, геолокации и внешней сети.
* Локальное хранение: персональные данные не собираются, базы SQLite и DataStore изолированы в песочнице приложения.
* Сброс данных: в родительском разделе предусмотрена кнопка полного сброса состояния для повторного тестирования сценария экспертами.
* Адаптация под детскую аудиторию: крупный шрифт (от 16sp), контрастные элементы, зоны нажатия от 48dp, отсутствие отвлекающих баннеров и всплывающих окон.
