# Техническое задание: Android-приложение «ФинПитомец» (FinPet)

## 0. Паспорт проекта и концепция

* **Название продукта:** «ФинПитомец» (FinPet) — мобильная обучающая игра с виртуальным питомцем.
* **Назначение:** Формирование базовых навыков личной финансовой грамотности у детей младшего школьного возраста (7–11 лет) через наглядную заботу о виртуальном друге.
* **Целевая аудитория:** 
  * *Ребёнок (7–11 лет)* — основной игрок: принимает самостоятельные финансовые решения, планирует бюджет, делает покупки, копит на цель, выполняет интерактивные квесты.
  * *Родитель / Взрослый* — поддерживающая роль: отслеживает прогресс компетенций в защищённом разделе, поощряет ребёнка бонусными монетами за реальные дела, управляет демо-режимом.
* **Образовательная основа:** «Единая рамка компетенций в области финансовой грамотности и финансовой культуры» (Минфин РФ / Банк России) для начального общего образования.
* **Целевая платформа:** Android 8.0+ (API level 26+), портретная ориентация, 100% Offline-first (работа без интернета).
* **Стек технологий:** Kotlin, Jetpack Compose, Material 3, Room SQLite, DataStore Preferences, Hilt DI, Kotlin Coroutines & Flow, kotlinx.serialization, Lottie Animation.
* **Идентификатор приложения (Package Name):** `ru.finpet.kids` (уникальный, валидный для RuStore, без запрещённых префиксов).
* **Границы конкурсного MVP (строго по ТЗ):** 
  * Полное отсутствие реальных денег, банковских карт, СБП, платных подписок и рекламы.
  * Нулевой сбор персональных данных (без регистрации, номеров телефонов, почты и трекеров).
  * Нулевые опасные разрешения Android (без камеры, микрофона, геолокации, контактов, интернета).

## 1. Архитектура и структура приложения

### 1.1. Архитектурный подход
Для обеспечения максимальной скорости и стабильности сборки на хакатоне используется **Single-module Architecture** с эталонным разделением по слоям (Clean Architecture + MVI/MVVM). Это предотвращает многочасовые конфликты зависимостей Gradle при multi-module структуре, при этом на 100% выполняет требование конкурса о разделении данных, бизнес-логики и UI.

```text
ru.finpet.kids/
├── core/
│   ├── data/            // Room DB, DAO, Entities, DataStore, JSON Content Loaders
│   ├── domain/          // Модели данных, Use Cases, калькуляторы экономики, валидаторы
│   ├── designsystem/    // Тема Material 3, цвета, типографика (≥16sp), кнопки (≥48dp), карточки
│   └── util/            // Хелперы, константы, форматирование валюты
├── feature/
│   ├── onboarding/      // Обучающий старт (3 карточки решений: обязательное, желаемое, копилка)
│   ├── petcreation/     // Создание питомца (27 комбинаций внешности, имя)
│   ├── home/            // Главный экран (питомец, статусы, быстрые переходы)
│   ├── budget/          // Планирование бюджета (3 корзины, остаток, План vs Факт)
│   ├── shop/            // Магазин товаров (обязательные/желаемые, защита от нехватки средств)
│   ├── goals/           // Копилка и цели (расчет сроков, подтверждение пополнения и снятия)
│   ├── quests/          // Интерактивные мини-сценарии с последствиями и моралью
│   ├── adult/           // Родительский раздел (математический гейт, прогресс, бонусы, сброс)
│   └── demo/            // Контроллер демо-режима для экспертов (переключение 5 периодов)
└── FinPetApp.kt         // Application класс, Hilt инициализация
```

### 1.2. Технологический стек
* **UI:** Jetpack Compose + Material 3, кастомная дизайн-система с крупными тач-таргетами.
* **Навигация:** Navigation Compose с типобезопасными маршрутами.
* **Асинхронность и реактивность:** Kotlin Coroutines + `StateFlow` / `SharedFlow`.
* **Внедрение зависимостей:** Google Hilt.
* **Локальная база данных:** Room 2.6+ (SQLite).
* **Легковесные настройки:** Jetpack DataStore Preferences.
* **Управление контентом:** Внешние JSON-файлы в `assets/content/`, парсинг через `kotlinx.serialization`. Изменение заданий и товаров не требует переписывания бизнес-логики.
* **Графика и анимации:** Векторная графика (Vector Drawable / Canvas) + Lottie Compose для живых реакций питомца.
* **Качество кода:** Unit-тестирование бизнес-логики (JUnit5, MockK, Turbine).

## 2. Игровая экономика и математическая модель

### 2.1. Игровая валюта и периодичность
* **Валюта:** Игровые золотые монеты (условные единицы, без реальной стоимости).
* **Игровой период:** 1 условный день / игровой цикл. В демо-режиме переключается мгновенно по нажатию кнопки «Завершить день».
* **Стартовый капитал:** `300 монет` (даётся при первом создании питомца).
* **Периодический доход:** `+100 монет` в начале каждого периода («Карманные деньги на период»).
* **Доход за задания:** `+20…50 монет` за успешное прохождение обучающего квеста.
* **Бонус от родителя:** `+10…50 монет` (начисляется взрослым в защищённом разделе).
* **Балансовое правило:** Баланс не может быть отрицательным. Любая попытка покупки при нехватке блокируется с дружелюбным объяснением.

### 2.2. Распределение личного бюджета (3 обязательных корзины)
До начала трат в периоде ребёнок распределяет доступные средства по 3 направлениям:
1. **Обязательные расходы ($Plan_{mand}$):** Еда, чистая вода, гигиена, лекарство.
2. **Необязательные расходы ($Plan_{opt}$):** Игрушки, лакомства, аксессуары.
3. **Накопления в копилку ($Plan_{sav}$):** Отчисления на выбранную финансовую цель.

**Валидация бюджета:**
$$Plan_{total} = Plan_{mand} + Plan_{opt} + Plan_{sav}$$
$$Plan_{total} \le AvailableBalance$$
$$Remainder = AvailableBalance - Plan_{total}$$
* На экране всегда отображается нераспределённый остаток.
* План можно свободно редактировать до нажатия кнопки «Утвердить бюджет». После утверждения он фиксируется и используется для подсчёта «План vs Факт».

### 2.4. Финансовые цели (Копилка)

| ID | Цель | Стоимость | Ожидаемый срок при взносе 50/период | Иконка / Визуал |
|---|---|:---:|:---:|---|
| `goal_house` | Уютный домик | 150 монет | 3 периода | Красивый домик для питомца |
| `goal_scooter` | Игрушечный самокат | 350 монет | 7 периодов | Быстрый транспорт для прогулок |
| `goal_friend` | Робот-друг для питомца | 600 монет | 12 периодов | Интерактивный компаньон |

* **Формула расчёта срока достижения цели:**
  $$\text{Периодов до цели} = \left\lceil \frac{\text{Стоимость} - \text{Накоплено}}{\max(\text{Средний взнос}, 10)} \right\rceil$$
* **Снятие средств из копилки:** Разрешено в любой момент, но требует двойного подтверждения. Диалог наглядно показывает: *«Если забрать 50 монет, покупка Домика отложится на 1 день. Точно забрать?»*.

### 2.5. Математика состояния и развития питомца

#### 1. Сытость ($S \in [0..100]$):
Зависит от закрытия базовой потребности в питании (минимум 30 монет на порцию еды за период):
$$S = \begin{cases} 
100, & \text{если куплен Сытный обед} \\
60, & \text{если куплена только Свежая вода} \\
30, & \text{если еда не куплена (питомец голоден, но жив!)}
\end{cases}$$

#### 2. Здоровье ($H \in [0..100]$):
$$H = \begin{cases} 
100, & \text{если } S \ge 60 \text{ и обязательные расходы выполнены} \\
60, & \text{если обязательные расходы не покрыты} \\
90, & \text{если питомец получил витамины после недомогания}
\end{cases}$$

#### 3. Настроение ($M \in [0..100]$):
Базовое значение: 60.
* $+15\dots 35$ за каждую покупку из необязательных расходов.
* $+10$ если отложены деньги в копилку по плану.
* $-20$ если допущен перерасход по необязательным тратам ($Actual_{opt} > Plan_{opt}$).
* $-30$ если питомец остался голодным ($S < 50$).
* Итоговое значение нормализуется: $M = \text{clamp}(M, 10, 100)$.

#### 4. Эмоциональный статус питомца (отображается на главном экране):
* **Радостный (`HAPPY`):** $S \ge 70$, $H \ge 80$, $M \ge 70$.
* **Обычный (`NEUTRAL`):** $S \ge 50$, $H \ge 60$, $M \ge 40$.
* **Грустный (`SAD`):** $S < 50$ или $M < 40$. Сопровождается обучающей репликой: *«Мне немного грустно, потому что мы забыли купить обед. Давай в следующий раз сначала купим корм!»*.

#### 5. Подсчёт соответствия плану (Plan vs Fact Compliance):
Для каждой из трёх корзин (где $P$ — план, $A$ — факт):
$$\text{Score}_i = \begin{cases} 
1.0, & \text{если } P = 0 \text{ и } A = 0 \\
\max\left(0.0, 1.0 - \frac{|A - P|}{\max(P, 1)}\right), & \text{если } P > 0
\end{cases}$$
$$\text{Общее соответствие плана} = \frac{\text{Score}_{mand} + \text{Score}_{opt} + \text{Score}_{sav}}{3} \times 100\%$$

#### 6. Очки роста (Care Points) и стадии эволюции питомца:
За каждый завершённый игровой период начисляются очки роста (максимум +4 очка):
* $+2$ очка: базовые потребности закрыты (питомец сыт и здоров).
* $+1$ очко: в копилку отложено не меньше запланированного ($Actual_{sav} \ge Plan_{sav} > 0$).
* $+1$ очко: общее соответствие бюджетному плану $\ge 75\%$.

**Стадии развития питомца (ТЗ 2.5.10):**
* **Стадия 1: «Малыш» (0–4 очка)** — маленький персонаж, базовые реакции.
* **Стадия 2: «Подросток» (5–9 очков)** — питомец подрастает, меняется анимация, открываются новые аксессуары.
* **Стадия 3: «Взрослый» (10+ очков)** — крупный, уверенный персонаж с праздничной анимацией и медалью бережливости.

## 4. Спецификация экранов и пользовательский путь (Приложение А)

Приложение гарантирует 100% бесшовное прохождение обязательного демонстрационного сценария (Шаги 1–12 Приложения А):

### 4.1. Онбординг (Шаг 1)
* 3 красочных слайда с крупными иллюстрациями и коротким текстом:
  1. *«Познакомься со своим питомцем и заботься о нём!»*
  2. *«Деньги любят счёт: делай обязательные покупки, радуй питомца и копи на мечту!»*
  3. *«Три правила бюджета: Сначала необходимое $\to$ Потом желаемое $\to$ Часть в копилку!»*
* Кнопка «Поехали!» без запроса регистрации и личных данных.

### 4.2. Создание питомца (Шаги 2–3)
* Выбор базового персонажа: Котёнок, Щенок или Дракончик.
* Кастомизация (3 цвета $\times$ 3 типа мордочки/глаз $\times$ 3 аксессуара = **27 уникальных комбинаций** при минимуме 9 по ТЗ).
* Ввод игрового имени (проверка на непустую строку, по умолчанию «Дружок»).
* Сохранение в Room без сетевых запросов.

### 4.3. Главный экран (Dashboard) (Шаг 4)
* **Анимированный питомец** по центру экрана (реагирует на тапы, мурчит/радуется при хорошем уходе).
* **Информационная шапка:** Доступный баланс монет, сумма в копилке, текущая цель с прогресс-баром.
* **Индикаторы состояния:** Сытость, Здоровье, Настроение (с цветовыми бейджами и понятными смайлами).
* **Быстрые кнопки навигации (крупные, $\ge 48 \times 48$ dp):**
  * «План бюджета» (подсвечивается в начале нового периода).
  * «Магазин».
  * «Копилка / Цели».
  * «Задания» (бейдж с доступными квестами).
  * «Итоги дня / План vs Факт».
  * Иконка замка «Родителям» в верхнем углу.

### 4.4. Экран планирования бюджета (Шаг 5)
* Карточки 3 корзин: Обязательное, Желаемое, Копилка.
* Удобное управление суммами кнопками `+10` / `-10` и быстрым выбором («Поровну», «Рекомендованный план»).
* Динамический счётчик: «Доступно: X», «Запланировано: Y», «Свободный остаток: Z».
* Защита от превышения баланса (кнопка утверждения блокируется при остатке $< 0$).

### 4.5. Экран магазина и механика покупок (Шаг 7)
* Переключатель фильтров: «Все», «Обязательные», «Желаемые».
* Карточка товара: картинка, название, бейдж категории, цена, прогнозируемый эффект на питомца.
* Нажатие на покупку вызывает диалог подтверждения: *«Купить за X монет? Сытость вырастет на +Y»*.
* **Кейс нехватки средств (Шаг 7 Приложения А):** Если монет недостаточно, кнопка покупки показывает красный индикатор и открывает поддерживающее окно: *«Ой, не хватает X монет! Не расстраивайся: ты можешь выполнить задание и заработать монетки или купить это в следующем периоде»* с кнопкой перехода в раздел «Задания».

### 4.6. Экран копилки и целей (Шаг 8)
* Выбор активной цели из 3 доступных.
* Круговой прогресс накопления и расчет: *«Осталось накопить 120 монет (примерно 3 периода)»*.
* Кнопка «Пополнить копилку» с выбором суммы.
* Кнопка «Забрать из копилки» с предупреждением о сдвиге срока цели.

### 4.7. Экран итогов периода (План vs Факт) (Шаги 9–10)
* Наглядная таблица сравнения по 3 корзинам:
  * Запланировано vs Потрачено фактически.
  * Индикатор дисциплины («План соблюдён на 85% — великолепно!»).
* Начисление очков роста питомца.
* Кнопка «Перейти в следующий день» (пересчитывает период, начисляет +100 монет карманных денег, запускает анимацию роста/эмоции питомца).

### 4.8. Раздел для взрослого (Parent Zone) (Шаг 12)
* **Защитный барьер:** решение арифметического примера (например, `14 + 18 = ?`) + удержание кнопки в течение 3 секунд.
* **Содержимое раздела:**
  1. *Образовательный прогресс:* Освоенные компетенции ребенка по Единой рамке с пояснениями.
  2. *Родительский бонус:* Возможность начислить ребенку 20, 30 или 50 монет за реальное достижение (уборка в комнате, чтение книги) — прямая связь игры с реальной жизнью.
  3. *Демо-панель для жюри:*
     * Переключатель «Демонстрационный режим» (включает быстрый переход между 5 периодами).
     * Кнопка «Сбросить демо-профиль» (возврат базы в идеальное исходное состояние для проверки с нуля).
     * Кнопка «Удалить все данные» (полная очистка Room и DataStore).

## 6. UX/UI и доступность для детей 7–11 лет

* **Размеры кликабельных зон:** Не менее $48 \times 48$ dp (основные кнопки — $56$ dp).
* **Типографика:** Размер основного шрифта — не менее $16$ sp, заголовки — $20\dots 24$ sp.
* **Текстовый контент:** Короткие предложения (до 8–10 слов), простые и понятные формулировки без банковского жаргона («траты на необходимое», «копилка», «желания»).
* **Мультисенсорное дублирование:** Статусы и категории обозначаются одновременно цветом, уникальной иконкой и текстом (доступность для пользователей с особенностями цветовосприятия).
* **Звук и тактильный отклик:** Мягкие звуки монет и мурлыканья питомца с возможностью полного отключения в один клик.
* **Безопасная ошибка:** Питомец никогда не умирает, не получает тяжелых травм и не бросает ребенка. Ошибка объясняется в форме поддержки и быстрого способа исправления (пройти квест, перенести покупку).
